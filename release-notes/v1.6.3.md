## 1.6.3

**以前遇到「需要重启」，页面只能告诉你这句话，然后呢就没有然后了。**

manager 报 `restart-required` 的时候，插件确实做不了那件事的最后一公里：桌面版的重启握在
应用外壳手里，从终端启动的宿主也没人替它拉起来。但「做不了」不等于「只能说一句『请重启』」——
页面至少能告诉你**在你这台机器上，到底是哪一个动作能把它重启掉**，并且在你做完之后**替你确认
真的重启了**。这一版补的就是这两步。

**提示条上多了一个「重启 DSH」按钮。** 点开之后：

- 桌面版 → 「完全退出 DeepSeek Harness（不是关窗口，而是退出应用），再重新打开它」。
- 从终端启动的 → 直接给出**当初那条命令行**（含空白的参数已经加好引号，可以原样粘贴），
  外加一个复制按钮。

这两个分支靠 `process.argv[1]` 判断，不猜环境变量：外壳拉起的就是
`dsh-desktop-host/lib/index.js`，别的启动方式不会落到那个路径上。终端那种情况能给出命令，
桌面那种情况**故意不给**——把子进程的 argv 重放一遍，等于在同一个 profile 上再起第二个宿主。

**然后是这一步：确认它真的重启了。**

对话框按下「重启好了，刷新页面」之后，不刷新，而是**每秒问一次宿主的 pid**（新增的
`GET /api/plugin-upgrader/host`），直到应答的那个 pid **不一样**了才往下走。接着刷新也不是
直接 `location.reload()`，而是走 1.3.0 加的那道 boot 文档守卫：新的宿主可能已经轮换到这一页
根本加载不了的那一代 batch，直接刷会撞上 `web boot: 3 entries did not activate`；被守卫挡住时
对话框会直说「请再重启一次 DSH」。

两个刻意加的限制：pid 是**每次现算**的，不缓存——缓存会让一次真的重启看起来像卡住；整段等待
**封顶两分钟**，超了就说「宿主还没换新进程」，而不是一直转圈。

**按钮挂在结果上，不挂在提示条的颜色上。** `warn` 这个色调还兼着「这一页没有提供安装入口」
和「刷新被拦住了」两种情况，只有其中一种是重启能解决的。所以是 `restart-required` 这个结果把
标志位立起来，下一次开新批次时清掉——建议一旦不再成立，按钮就消失。

**等待失败有两种，说法不一样。** pid 一直不变，说明旧进程还活着；pid 变了、页面却刷不上去，
说明新的宿主已经接不上这一页，得再重启一次。这两种以前都印同一句话（「宿主还没换新进程」），
于是第二种情况的人会去找一个早就不存在的进程。
