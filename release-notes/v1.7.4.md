# 1.7.4 — 让搜得到

这一版没有改功能。它改的是**一句描述**，以及由此暴露出来的一个事实：这个插件在 npm 上基本搜不到。

## 问题

如果有人不知道这个插件的名字，他是搜不到它的。实测（2026-11-04，npm registry 搜索 API）：

| 搜什么 | 我们排第几 |
| --- | --- |
| `dsh-plugin-upgrader` | 第 1 —— 但前提是你已经知道名字 |
| `upgrader` | 第 8（共 90 条） |
| `dsh-plugin` | **第 368**（共 302,030 条） |
| `dsh plugin` | 第 353（共 330,772 条） |
| `plugin manager` | **前 750 没有** |
| `dsh` | **前 750 没有** |
| `version-manager` / `plugin-manager` | **前 250 没有** |

月下载 3182，却排在月下载 185 的包后面。

## 为什么

npm 的相关度分数里，`popularity` / `quality` / `maintenance` 三项在所有候选身上**都是 1.0**，所以差异 100% 来自文本匹配。把前 500 名按「描述里有没有独立的 `dsh` 这个词」分组：

- 有：459 条，中位数 **118.3**
- 没有：40 条，中位数 **103.0**

我们是那 40 条里的一个（103.05）。因为描述写的是

> One-click upgrades, version history and rollback for plugins on the **DeepSeek Harness** Plugins page

——通篇「DeepSeek Harness」，**一次「DSH」都没有**。

把描述长度控制住（只看 10–26 个词）差距依然在（123.9 对 112.9），所以起作用的确实是那个词，不是长短。而**关键词数量完全没用**：同分组内 kw 0–1 的 139.9、kw 6–10 的 142.3、kw 10+ 的 129.6；`@jieai/dsh-plugin-vet` 堆了 32 个 keyword，分数 93.9。

这是个很常见的坑，不是我们独有：`dsh-plugin-ops`（103.1）、`dsh-plugin-shop`（103.5）、`@loongsuite/dsh-plugin`（103.0）、`dsh-plugin-security`（103.6）全都是同一个原因——只写全称，不写缩写。而 `dsh-plugin-mgr` 描述写 `DSH plugin that manages installed plugins…`，215.1。

## 改了什么

`package.json` 的 `description` 和 `keywords` 按「人们实际怎么搜」重写：描述里同时带上 `DSH` 和 `DeepSeek Harness`，关键词补充了 `deepseek`、`harness`、`cordis`、`upgrade`、`rollback`。

除此之外没有代码改动、没有行为变化、没有新增依赖。

## 顺带说一句

如果你也在做 DSH 插件，去搜一下自己包在 `dsh-plugin` 这个词下的名次。前 250 名的门槛只要月下载几百，排不进去基本就是描述的问题，改一句话的事。

升级：

```
dsh plugin --profile web add dsh-plugin-upgrader
```
