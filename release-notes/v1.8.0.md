# 1.8.0 —— 装不了的那个版本，不再是一条死路

这一版没有新架构，只有一件事：**把「你装不了」从一句话变成一条能走的路**。

起因是一次数据观察。这页的下载量里，发版日是安静日的 8.3 倍，而 `latest` 在逐版本下载里
占比 0.0% —— 说明那些「下载」大多是镜像和目录站在遍历 packument，不是人在装。继续铺渠道
的边际收益接近 0（当时 12 个 PR、3 个 issue、5 条技术评论、1 篇自荐贴，全部零回复）。
所以转向了留下来的那批人：**装了插件的人，在升级 DSH 之后不能静默失效**。

## 最新版装不了时，给出能装的那个

宿主的兼容性闸门是**在 bundle 已经卸下之后**才拒绝的（那是 1.5.0 的预检存在的原因）。
所以「最新版你装不了」这句话如果不配一个替代方案，那一行就彻底没有可点的动作了 ——
而实际上旧一档的版本明明装得了。

现在每一行会带上 `recommended`：**高于已装、并且这台宿主真的能装**的最高版本。
按钮从「升级」变成「升级到 1.1.0」，批量升级和「升级选中」也走同一个目标。

它有两个刻意的边界：

- **永不高于 `latest`**。tag 之后发布的预发布版不会被这个页提拔（同「坏 tag」那条规则）。
- registry 没有 `dist-tags.latest` 时**不推荐**，而不是凭空造一个目标。

## 「你现在跑的这个」也会不兼容

上面那句话是从 `latest` 算的。如果**已安装**的那个版本声明的 DSH 范围，在你最近一次
升级 DSH 之后就出界了，插件很可能根本没被加载 —— 而升级按钮救不了它，因为升级失败的前提
是它先能被卸载。

这种行现在单独说一句：「已装的 1.0.0 要求 DSH ≥0.2.0，当前宿主不满足」。它和
「最新版装不了」是两个不同的字段、两句不同的话：一个是「新东西用不上」，另一个是
「你现在这个是坏的」。

`runtimeVersion` 读不到时**什么都不判**。不知道不能写成不兼容。

## 一个能归零的「需处理」

顶部多了一项统计，只数**这个 profile 里真的出了问题**的插件：

| 计入 | 不计入 |
|---|---|
| 已装版本不兼容 | 「有新版本但你装不了」（那不是你能修好的状态） |
| 镜像落后（上游有、镜像没有） | 普通的「可升级」（那是好事） |
| 版本读不到 | |
| 有构建待批准 | |

点它只列这些行，并且**和搜索框叠加**。这个数字能归零，才有意义 —— 一个永远大于零的红色
徽章只会训练人忽略它。

## 版本错误现在是中文

那六句话是宿主返回的**固定英文 API 值**（`'registry lookup failed'`、
`'local path install: the registry has no published copy'`、
`<kind> source: no registry history` 之类），它们一直是原样透到中文界面上的。现在在客户端
翻译一遍，host 侧一个字节都没改（那是对外数据）。

**不认识的原样透传。** `registry unreachable: fetch failed (ECONNREFUSED)` 那种句子翻译了
就没法搜，而且它常常是整行唯一的线索。

## 一键复制诊断信息

把 DSH 版本、registry、时间戳、每一行插件与它的每个问题拼成一段 markdown，贴进 issue 就行。
纯客户端：不加路由、不发请求、不新增任何能力声明。

## 页脚写明你跑的是哪个 DSH

这个页面所有兼容性判断都基于它，而它此前从来没被显示过。读不到时页脚会如实说「DSH 版本
未知」，而不是留空让人以为没问题。
