## 1.5.0

**这个包现在能在 DSH Store 的固定 commit 审核里通过所有「包自己能控制的事情」。**

Store 只看一个 commit 的文件树，按 `files` 找运行时文件，并且拒绝执行 `prepare` 去补齐它们。
由此产生三处改动：`lib/` 从被忽略变成提交进仓库；构建从 `prepare` 挪到 `prepack`（所以安装
期不再执行任何脚本）；`engines` 除了 `node` 还声明了 `dsh`。拿 Store 自己的审核代码对暂存树
重跑一遍，理由从七条降到三条：缺产物、`prepare` 生命周期脚本、未声明 DSH 版本范围，以及
不完整的扫描——全部消失。

**一道守卫让提交进去的产物保持诚实。** `scripts/verify-build-committed.mjs` 把磁盘上的 `lib/`
和索引比对，并且 `pnpm run check`、CI、发布流程都会跑它——改了 `src/` 忘了重建，就到不了
registry。这要有意义，构建必须是可复现的，而它是：连续两次构建产出逐字节相同的输出。

**剩下的三条理由是插件真实的能力**，Store 把它们转给人工复核通道而不是拒绝：它读写 profile
manifest（`files`），它抓 packument（`network`），它读环境变量来定位 profile（`credentials`
——`DSH_PROFILE_DIR` 和 `DSH_PROFILE`，都不是秘密；Store 的良性变量白名单里有 `DSH_HOME`
但没有这两个）。
