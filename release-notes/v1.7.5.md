# 1.7.5 —— 装回去了，但它没跑起来

一次升级失败之后，插件有两种完全不同的结局：

- 旧版本**装回来了，也跑起来了** —— 你看到的是一个还能用的插件，只是没升级成功。
- 旧版本**装回来了，宿主却没把它激活** —— 文件在盘上，可页面上没有它。

以前这两种都只说一句话：`xxx@1.0.0 is not installed — install it again from the Installed tab`。
第二句是错的，而且照着做不会成功 —— 包明明装着，宿主会回你一句 `already-installed`。

官方也有同一个毛病，`deepseek-ai/deepseek-harness` 的
[#11886](https://github.com/deepseek-ai/deepseek-harness/discussions/11886) 里，
报告人就是这么走了一圈：对话框说"not installed"，他去点 Add plugin，得到 `already-installed`。

## 现在会怎么说话

| 结局 | 面板 | 日志 |
|---|---|---|
| 装回来了，也跑起来了 | 正常「升级失败」 | `✓ xxx@1.0.0 is back where it was` |
| 装回来了，没激活 | **单独一行**：文件在盘上、去「已安装」里重新启用、别重装 | `! xxx@1.0.0 is installed but did not activate (原因); the package is back on disk - enable it again from the Installed tab` |
| 真没装回来 | 正常「升级失败」 | `! rollback refused (...); xxx@1.0.0 is not installed — install it again from the Installed tab` |

## 怎么判断的

`application` 一个字段不够 —— 它只回答「插件最后跑起来没有」。落盘但没激活时它是
`failed`，而 pnpm 压根没成时它也是 `failed`。要三个独立信号同时成立才敢说「装了没激活」：

- `changed === true`：profile 被改写过了；
- `stage === 'enable'`：宿主已经走到激活那一步；
- `packageResult.exitCode === 0`：pnpm 这一趟是干净的。

三个都满足 = 文件在、只是没跑。任何一个不满足 = 按「没装」说。

## 顺带

- `StepOutcome` / `StepResult` 新增 `inactive` 与 `rollbackReason`；`rolledBack` 含义未变
  （旧版本**可用**了），不会为「文件在但没跑」填。
- 中英文案各加一条 `inactiveAfterRollback`，其优先级高于通用失败拼接。

升级：

```bash
dsh plugin --profile web add dsh-plugin-upgrader
```

如果你在用 1.7.4 或更早，遇到「升级失败、插件从页面消失、让你重新安装」时，
**先去「已安装」里看看它是不是还在** —— 装回去但没激活的包，重新启用就能回来。
