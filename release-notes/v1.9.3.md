# 1.9.3 —— 「需处理」不再数一句「版本从哪来」

上一版在 README 里**承认**了这个缺陷，没有修。这一版修掉了。

## 症状

徽标上那个数字归不了零。点进去看，唯一那一行是本插件自己——`link:` 装进来的开发副本——
而那一行上没有任何按钮。

原因是 `needsAttention()` 数的是「`versionError` 非空」，而这个字段里装着两种毫不相干的东西：

- **查了，但失败了**：registry 超时、限流、包压根没发布过。这是真的需要你去处理。
- **一句说明**：本地路径安装没有可比对的注册表副本、`git:` / tarball 安装没有发布历史、
  安装目录里自带的 bundle 不归 profile 管。宿主管这些也叫 `versionError`，但它们是**来源**，
  不是故障。

后三种根本轮不到「查」，页面也做不出任何动作。把它们数进去，就等于承诺了一个并不存在的
待办事项。

## 判据

现在问的是「这一行本来会不会去 registry 查版本」：

```ts
function versionIsLookedUp(row: OverviewRow): boolean {
  return row.managed === true && (row.kind === 'registry' || row.kind === 'unknown')
}
```

`unknown` 必须留着。真实 profile 里绝大多数正常依赖的 `source` 都解析成 `unknown`
（`sourceKind()` 认不出一个裸的 `name@range`），把 `unknown` 排除掉，等于把整页插件一起排除——
那是另一个方向的误报，更难发现。

## 没有改的地方

宿主侧那六句 `versionError` 一个字都没动。`test/self-row.test.ts` 逐字断言其中的原文，而且
`PluginRow` 拿同一个字符串当**描述行**（`row.description ?? versionNote ?? row.name`）：
删掉之后，这类行就只剩一个包名了。

真正失败的那些行照旧计数，行上的「重试」按钮照旧出现。收窄的是**哪些行会被问**，不是
**失败长什么样**。

## 测试

`test/diagnostics.test.ts` 新增三条：

- `link:` / `file:`、git、tarball、未托管行的说明句**不**计入；
- 托管且 registry 源的行，真失败的句子仍然计入；
- `versionError: ''` 仍然不计入。

把 `versionIsLookedUp` 改成恒 `true` 跑了一遍，第二条用例能红——不是摆设。全仓 `pnpm run check`
全绿，383 条测试。

两份 README 同步更新：表格里那一行改成「版本查不到」，来源说明挪进「刻意不算进去的」列表。

## 一句实话

这不是「修了一个 bug」，是**删掉了一个永远不会变成 0 的计数**。数字只有真能归零，才值得你抬头看它。

升级：

```bash
dsh plugin --profile web add dsh-plugin-upgrader
```
